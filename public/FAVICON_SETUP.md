# Favicon setup (Phase 9)

The favicon assets you pasted live in `public/` after this commit. Because
`index.html` was generated by Vite when the project was scaffolded, it still
points at the old `/vite.svg`. Per repository convention, `index.html` was
*not* edited in this change — apply the merge below yourself.

## Step 1 — drop the icon files into `public/`

Copy these (the file names must match the link tags exactly):

```
public/
├── favicon.ico
├── favicon.svg
├── favicon-96x96.png
├── apple-touch-icon.png
└── site.webmanifest
```

A working `site.webmanifest` is already provided in this folder (see
`site.webmanifest` next to this file). Replace its contents with your real
manifest if you have one.

## Step 2 — replace the favicon `<link>` in `index.html`

Open `index.html` and replace this line:

```html
<link rel="icon" type="image/svg+xml" href="/vite.svg" />
```

with the full block:

```html
<link rel="icon" type="image/png" href="/favicon-96x96.png" sizes="96x96" />
<link rel="icon" type="image/svg+xml" href="/favicon.svg" />
<link rel="shortcut icon" href="/favicon.ico" />
<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png" />
<meta name="apple-mobile-web-app-title" content="MyWebSite" />
<link rel="manifest" href="/site.webmanifest" />
```

## Step 3 — verify

After `npm run build`, the assets appear at the build root:

```
dist/
├── favicon.ico
├── favicon.svg
├── favicon-96x96.png
├── apple-touch-icon.png
└── site.webmanifest
```

Open `dist/index.html` and confirm the `<link>` tags are present. Browsers
will then load the icons from `/favicon.ico` etc. at runtime.

## Why `index.html` wasn't edited

`index.html` is static template config; it is on the no-augment list for
this commit. The merge is a single-line find/replace and is intentionally
left as a one-time manual step.
